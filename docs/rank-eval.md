# /rank 排序评测（2026-10-19）

评测对象：`scripts/rank.py`（与网站“为我推荐”的 `assets/rank.js` 同一套规则，测试保证两边结果逐条一致）在
2026-10-19 的 `assets/catalog.json`（现在可申请的机会 2631 条）上，对虚构画像给出的**前 10 条**。

```bash
python scripts/rank_eval.py              # 打印每个画像的前 10、人工标注（✓ / ✗ / ? 未标注）与准确率
python scripts/rank_eval.py --only p03-medimg
```

画像在 `tests/rank_eval_profiles.yml`，人工标注在 `tests/rank_eval_labels.yml`（按机会 id 记录；数据更新后重跑，只需给新出现的条目补标）。

## 判断标准

由产品 C 会话逐条阅读标题与简介后判断，**1 = 按这个画像，这条值得出现在前 10**：

- 研究方向要真对口，不是字面巧合（“RNA Polymerase”不是高分子，“tissue history”不是历史学，“Ecosystem Orchestration”里的生态系统是比喻）；
- 方法类关键词用在别的领域、需要另一门学科背景的，算不对口（“Machine Learning for Dark Matter Detection”之于做强化学习 / 机器人的人）；
- 面向所有学科的大项目（如西班牙 FPU、EUI 奖学金）若明确包含该方向，算对口；
- 硬性条件（国家、层次、截止、资助）由程序先筛过，标注时不再考虑。

准确率 = 前 10 条里标 1 的条数 ÷ 前 10 条总数（推荐不足 10 条的按实际条数算）。

所以 `/rank` 命令里让 Claude 再读前 N 条的简介逐条判断（值得投 / 可以考虑 / 不太合适），网站上每张卡片都写明命中了哪个词、在标题还是简介里，方便自己排除。
诚实说明：标注人也是调规则的人，p01–p20 的 81% 偏乐观；留出组的数字更能代表真实效果。

## 评测中改过的规则

第一版（关键词同义词全展开、只要学科相同就推荐）在 p01–p20 上前 10 几乎全是凑数，逐轮改为：

1. **不凑数**：只推荐标题或简介命中关键词的机会；只是学科相同的单列为“学科相同、未命中关键词”，不进推荐。
2. **同义词与更窄的词分开**（“医学影像 > MRI、超声成像”）：关键词只按同义词归组，匹配时才用更窄的词；“MRI”不会再扩到所有成像。
3. **复合关键词要各部分都命中**（“植物免疫”= 植物 + 免疫），只命中一部分记一半分；“神经网络”不会被当成“神经（科学）”。
4. **学科不能冲突**：岗位学科与画像学科对不上的命中丢弃（“immune memory”“spintronic memory”之于认知神经科学）；弱命中要求学科明确对得上。
5. **去掉资助方 / 机构名再匹配**（“Economic and Social Research Council”不等于经济学、“National Institute of Education”不等于教育学）；
   Varbi 的“PhD student in <系名>, focus on <方向>”只用方向部分。
6. **短中文词只用来归组**（“控制”“环境”“经济”“材料”“自动化”在简介里太常见，不拿去匹配）。
7. **方法类关键词用在别的学科打对折**（“Machine Learning for Dark Matter”）；人工智能与计算机视为同一方向。
8. **常见关键词降权**：命中条数越多，每次命中的分越低。
9. **权重**：研究匹配从 60 提到 70 分，资助 / 截止 / 地区 / 资格合计 30 分，避免“官网未写明资助”压过方向对口。
10. **北欧 / 荷兰语公告**按语言条件排除（画像 `languages.other` 写了该语言才保留）。
11. 留出第一组暴露的问题：`polymer*` 误配 polymerase、`statistic*` 误配 statistical physics、`transport` 误配电子输运——改为更具体的词。

## 已知局限与下一步

- 只看标题、简介和学科：岗位原文里的具体课题、导师方向没有用上；同一个词的不同含义（“免疫”在肿瘤免疫与感染免疫里）分不开。
  下一步（路线图第 6 项）：50 个画像的金标准评测；对前 N 条加向量相似度与模型打分。
- 岗位的学科是按标题归类的（`build_site.py` 的 `DISC_WORDS`），归错会直接影响“学科冲突”判断（例如把“tissue history”归到人文）。
- 结构化的学位、语言、开始时间字段（工程 A 在做）覆盖后，硬性筛选会更准；目前只有少数岗位有这些字段，没写的条件一律不排除。
- 数据会每天变化：重跑 `scripts/rank_eval.py` 时新出现的条目显示为“?”，补标后再看准确率。

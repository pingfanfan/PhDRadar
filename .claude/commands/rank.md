---
description: 按申请者画像给现在可申请的机会排序（硬性筛选 + 打分），再由 Claude 读前 N 条简介写一句话判断
argument-hint: [前 N 条做判断，默认 10] [--top 30]
---

1. 没有 `profile.yml` 就先让申请者运行 `/setup`（或复制 `profile.example.yml` 修改），然后停下。
2. 数据：`assets/catalog.json` 由每日任务更新。若文件超过 2 天没更新，先 `git pull --rebase` 再排序。
3. 运行 `python scripts/rank.py --top 30`（`$ARGUMENTS` 里有 `--top` 就照用）。它写出：
   - `rankings/<今天>.md`：前 30 条，每条三行理由 + 官网链接；被排除的按原因统计，并列出方向对口但被排除的；
   - `rankings/<今天>.json`：前 50 条的完整数据（含岗位简介 `in`、申请须知 `rq`、官网原句 `o.q`）。
4. **Claude 判断**（N 取 `$ARGUMENTS` 里的数字，默认 10）：读 `rankings/<今天>.json` 的前 N 条，结合 `profile.yml` 的
   `research.interests`、`publications`、`projects`，对每条写**一句话判断**：
   - 方向真的对口吗（关键词命中可能只是字面巧合，例如 “imaging” 用在显微成像而非医学影像）；
   - 申请者哪段经历最相关（只引用 `cv-facts.yml` / `profile.yml` 里有的）；
   - 有什么需要先确认的（资格待核实、要求先联系导师、截止时区等）。
   结论分三档：**值得投** / **可以考虑** / **不太合适**，写进 `rankings/<今天>.md` 末尾新的一节“Claude 的判断”，按档次排列。
   只根据数据里的文字判断；需要更多信息时可以打开官网链接读原文，但不要编造岗位没写的条件。
5. 向申请者汇报：值得投的几条（标题、机构、截止、链接、一句话理由）；即将截止（14–21 天）的单独提醒；
   被排除最多的原因（例如“雅思 6.5 不够的有 12 条”），以及放宽哪个条件能多出哪些机会。
6. 提醒：资格写“待核实”的，投递前请自己读官网确认；截止时间以官网为准，注意时区。`rankings/` 不会被提交。
